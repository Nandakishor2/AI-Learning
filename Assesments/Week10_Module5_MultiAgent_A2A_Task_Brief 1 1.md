# **What this week is about**
---“Multi-agent” — several AIs working together — is the most hyped idea in AI right now. This week you run the honest experiment: build a small team of specialist agents, race it against your single agent on the same tests, and keep whichever actually wins. Often the single agent wins, and that’s a valuable finding.
# **Why it matters**
---

| **Isn’t a team of agents always better than one?**Usually not. Every hand-off between agents re-sends everything, so a team can cost several times more for the same or worse result. You have to measure. | **When does multi-agent genuinely help?**When parts of the job are truly independent and can run in parallel, or need clearly different instructions. | **What is A2A?**Agent-to-Agent — a standard for one agent to hand work to another. MCP connects an agent to tools; A2A connects an agent to other agents. |
| --- | --- | --- |
# **What you’ll learn**
---- The main pattern: one “manager” agent splits the work and hands pieces to specialist agents

- Designing narrow specialists with focused jobs

- The hidden cost: every hand-off re-sends the whole context, so teams get expensive fast

- Racing the team against your single agent on the same tests — fairly

- Comparing on four things: quality, speed, tokens used, and cost

- A2A: the standard for agents handing work to each other, and where it fits
